## prompt 缓存顺序调查（DataAgent python-backend）
- 用户观察到模型输入渲染为 `[system] [messages] [tools]` 顺序，担心 tools 排后面导致无法命中前缀缓存。
- 定位：
  - `[system]…[messages]…[tools]` 日志格式来自 `app/infrastructure/llm/openai.py:141-149`（`llm input BEGIN` 日志，受 `llm_log_io` 控制）。
  - 真实请求在 `openai.py:_request()` 第 151-168 行：`messages=[system, *normalized_messages]`（system+对话），`tools` 为顶层参数排在 messages 之后。
  - system 来自 `prompts.py:45` AGENT_SYSTEM（静态）；messages 来自 `analysis.py:112` 的 `AgentContextBuilder.build`（每轮增长）；tools 来自 `tools.py:432` specifications()（静态）。
- 结论：栈为 OpenAI 兼容接口（Moonshot/Kimi）。OpenAI 风格前缀缓存的序列化顺序即 system→messages→tools，tools 在变长对话之后，故 tools 大块无法进入稳定前缀、每轮重算。用户担忧成立。
- 修复方向（未实施）：① 换支持 cache_control breakpoint 的模型（Claude）最干净；② 把 tools 注入 system 文本会丢失原生 tool_calls，不推荐；③ OpenAI 下只能保证 system+未变对话命中缓存，tools 缓存取决于 provider 内部序列化顺序。
- 用户尚未要求改代码，仅定位+解释。待确认是否要压缩 messages 动态字段以最大化前缀命中。
