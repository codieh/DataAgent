## 修复前端（data-agent-frontend）启动后空白页

- 现象：`npm run dev` 能起，但桌面窗口空白/打不开；dev 日志报 `electron' does not provide an export named 'BrowserWindow'`，且 `Electron --version` 返回 `v24.15.0`（Node 版本而非 Electron 版本）。
- 根因：环境里继承了 `ELECTRON_RUN_AS_NODE=1`（非 shell 配置，来自父进程/沙箱）。该变量会让 Electron 二进制"伪装成 Node 运行"，导致主进程在普通 Node 下加载 → `BrowserWindow` 命名导出失败 → 主进程崩溃、窗口建不起来。Electron 二进制本身完好（取消该变量后版本为 v40.10.2）。
- 修复：在 `package.json` 的脚本里固化去除该变量——
  - `"dev": "env -u ELECTRON_RUN_AS_NODE vite"`
  - `"build": "env -u ELECTRON_RUN_AS_NODE sh -c \"tsc && vite build && electron-builder\""`
  （macOS/Linux 生效；Windows 需用其它方式 unset。验证通过：npm run dev 后 Electron 进程正常拉起、报错为 0。）
- 排查命令备忘：`ELECTRON_RUN_AS_NODE= node_modules/.bin/electron --version` 应返回 Electron 版本；`env | grep -i electron` 查看该变量来源。

## 梳理 DataAgent「工具」注册/发现/调用机制（data-agent-python-backend）
- 当前为**静态集中式**注册，无运行时动态发现（无 MCP/Skill 市场/插件中心；架构文档 §21 明确第一阶段不做）。
- **注册**：`app/workflow/tools.py` 的 `AnalysisToolRegistry._build()` 用 LangChain `@tool(name, description=...)` 把异步函数声明为工具，末尾硬编码进 `tools: list[BaseTool]`；每个工具注入 `Annotated[AnalysisState, InjectedState]` 与 `Annotated[str, InjectedToolCallId]`，返回 `Command`（`_command()` 写状态增量 + ToolMessage）。`core_memory` 工具仅在依赖非空时条件追加。
- **装配**：`app/workflow/nodes/analysis.py` 的 `AnalysisNodes.__init__` 实例化 registry 并注入 db/retriever/python_analysis/result_history/core_memory 等业务依赖。
- **发现**：`AnalysisToolRegistry.specifications()` 把工具转成 `{name, description, parameters}`（刻意剥离 Injected 参数），在 `agent_decide` 节点通过 `llm.complete_tool_messages(..., tools=specifications())` 作为 function-calling 定义传给 LLM（`LlmClient` 协议见 `workflow/ports.py`）。
- **调用**：`graph.py` 中 `add_node("tools", LoggingToolNode(tool_registry.tools))`；`agent_decide` 后由 LangGraph 预置 `tools_condition` 路由：有 tool_calls 去 `tools` 节点（继承 `ToolNode` 的子类，执行前后记日志），按 name 分发执行并回填 ToolMessage；之后路由到 `sql_validate`(确定性安全检查)→`human_feedback`→`sql_execute`→ 回到 `agent_decide` 循环，或去 `result` 结束。
- 一句话：新增工具 = 在 `tools.py` 加一个 `@tool` 函数并加进 `tools` 列表即可，`specifications()` 会自动带上。
