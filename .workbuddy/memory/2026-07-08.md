## 调研:DataAgent 的 Excel 导出功能
- 用户以为 Python 后端 / 前端有 Excel(.xlsx)导出功能,实际**不存在**。
- 后端导出实现:`data-agent-python-backend/app/api/routes/results.py` 的 `export_run`(GET `/api/v1/runs/{run_id}/export`)。
  - `format` 仅支持 `csv|markdown`(正则限制)。
  - CSV 用标准库 `csv.DictWriter` 写入 `io.StringIO`,带 UTF-8 BOM(`utf-8-sig`)→ Excel 可直开不乱码。
  - 数据来源:取最后一个 query 的 result_set,经 `AnalysisDatasetStore.read_rows(offset=0, limit=total_rows)` 读全量行。
  - 无 openpyxl / pandas.to_excel / xlwt 等依赖。
- 前端"导出"按钮:`data-agent-frontend/src/screens.tsx` 第 116 行,仅为 `<a href="${backendUrl}/api/v1/runs/${run.id}/export?format=csv">` 链接,无客户端 xlsx 生成;`package.json` 无 SheetJS/exceljs。
- `/bootstrap` 接口的 `features.exports=True` 仅表示支持导出(CSV/Markdown)。
- git 历史、dist 产物均无 xlsx 相关代码/提交。
- 用户感知的"Excel 导出"= 下载带 BOM 的 CSV,Excel 打开即表格。

## 实现:新增真正的 .xlsx 导出
- 应需求,在后端 `export_run` 新增 `format=xlsx` 分支:
  - `pyproject.toml` 增加依赖 `openpyxl>=3.1.0`(已装入 managed venv 验证,版本 3.1.5)。
  - `format` 正则改为 `^(csv|markdown|xlsx)$`。
  - xlsx 分支:用 `openpyxl.Workbook()` 建表,`sheet.append(...)` 写表头+行,`io.BytesIO()` 内存缓冲,`workbook.save(buffer)` 后 `StreamingResponse` 返回,`media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"`,`Content-Disposition: attachment; filename="{run_id}.xlsx"`。
- 前端 `screens.tsx` 第 116 行"导出"按钮链接改为 `format=xlsx`(CSV 仍可用,改回参数即可)。
- 已用相同逻辑生成示例文件 `/Users/pengjie/code/github/DataAgent/sample_export_demo.xlsx` 验证可用。
- **下载技术栈要点**:后端只在内存里生成字节流(FastAPI `StreamingResponse`)+ HTTP 响应头 `Content-Disposition: attachment` 告诉浏览器"这是要下载的文件";前端只是一个普通 `<a>` 链接,浏览器原生触发下载,无需 FileSaver 等库。整个流程只有"下载",没有"上传"。

## SQL 结果 → 导出表的完整数据链路(用户追问"之后怎么变")
- ① `database.execute_select(sql)`:`sql.py` 的 `_execute_sync` 用 SQLAlchemy 跑只读 SELECT,`result.fetchmany(limit)` 取行 → `rows=[{列名:值}]`;列类型由 `_infer_type(rows,key)` 从实际值反推(bool/int/number/datetime/date/string),`columns=[{name,label,dataType}]`。
- ② workflow 的 `sql_execute` 节点(analysis.py:226-229)拿到 (columns,rows) 后调用 `dataset_store.create(run_id, columns, rows)`。
- ③ `dataset_store.create`(datasets.py)做两件事:**全量行**写成磁盘 CSV(`analysis_dataset_dir/{id}.csv`,`_csv_value` 把 None→""、日期→ISO 文本化);SQLite `result_sets` 表只存**预览行**(`analysis_dataset_preview_rows` 行)+ 列信息 + total_rows + truncated + file_path + storage_type="csv"。行数超 `analysis_dataset_max_rows` 直接报错。
- ④ workflow 结束后 `executor._persist_query_result`(executor.py:361)取 `query_results[-1].datasetId`,建 `QueryModel` 并设 `result_set_id=result_set.id`,把 query 和 result_set 关联;`list_queries` 按 created_at 排序,导出时取 `queries[-1].result_set_id`。
- ⑤ 导出时 `read_rows` 读**磁盘 CSV 全量**,`_read_csv_rows` 按 `dataType` 把文本还原成 int/float/boolean(空串→None)。若磁盘文件因 TTL/磁盘配额过期,storage_type 翻成 "sqlite" 仅留预览,导出报"完整结果文件已过期"。
- 关键"变化":原生 DB 类型 →(落盘成纯文本 CSV)→ 读取时按 dataType 还原;SQLite 故意只留预览用于快速列表,全量在磁盘。
