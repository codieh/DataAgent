# DataAgent 前端产品需求文档

> 文档状态：V0.1（界面重构前的功能定义）  
> 产品形态：Electron 桌面客户端  
> 核心定位：通过自然语言完成数据查询、分析与结果解释的 Agent 工作台

## 1. 产品目标

DataAgent 前端不应只是一个接口调试页面，而应成为用户与数据分析 Agent 协作的桌面工作台。用户只需要描述问题，客户端负责展示 Agent 的执行过程、分析结果和必要的人工确认，并保留可继续追问的上下文。

本轮重构优先解决三个问题：

1. 让用户能够像使用聊天工具一样自然地发起和继续数据分析。
2. 让 Agent 的多阶段执行过程清晰可见，但不过度暴露底层调试信息。
3. 让结果不仅能“返回”，还要适合阅读、核对和继续使用。

## 2. 目标用户

- **业务人员**：不熟悉 SQL，希望直接用自然语言查询数据。
- **数据分析人员**：需要查看 Agent 生成的 SQL、执行过程和结构化结果。
- **开发与调试人员**：需要确认 SSE 事件、payload、节点状态和错误信息。

界面默认服务于业务用户，技术细节放入可展开的详情区或开发者模式中。

## 3. 产品结构

客户端建议采用三栏式桌面布局，并允许用户调整各区域宽度：

```text
┌──────────────┬──────────────────────────────┬────────────────────┐
│ 会话与导航   │ 对话与分析结果               │ 执行过程 / 详情    │
│              │                              │                    │
│ 新建会话     │ 用户问题                     │ 当前阶段           │
│ 历史会话     │ Agent 回复                   │ 执行步骤           │
│ 数据源       │ 表格 / 图表 / SQL            │ 原始事件           │
│ 设置         │ 输入框                       │ Payload            │
└──────────────┴──────────────────────────────┴────────────────────┘
```

- 左栏可以折叠，主要负责导航和历史会话。
- 中间区域是核心工作区，始终优先保证阅读和输入空间。
- 右栏默认展示简洁的执行进度，也可以切换到技术详情，并支持收起。
- 窗口缩小时，右栏自动收起；移动尺寸下左栏以抽屉形式出现。

## 4. 核心功能

### 4.1 会话管理

- 新建会话。
- 展示历史会话列表，并按今天、最近 7 天、更早分组。
- 根据首个问题或分析主题自动生成会话标题。
- 切换会话后恢复聊天记录、线程 ID 和已有分析结果。
- 支持重命名、删除和搜索会话。
- 支持清空当前会话，但需要二次确认。

第一版可以先使用本地存储保存会话，后续再接入后端持久化接口。

### 4.2 对话输入

- 支持多行自然语言输入。
- `Enter` 发送，`Shift + Enter` 换行。
- 请求执行期间，发送按钮切换为“停止”。
- 支持常用问题示例，帮助首次使用者快速开始。
- 支持围绕当前结果继续追问，并复用当前 `threadId`。
- 空输入、超长输入和后端不可用时给出明确提示。

后续能力可以包括文件上传、语音输入、问题模板和 `@数据源` 选择。

### 4.3 Agent 回答展示

- 区分用户消息、Agent 回复、系统提示和错误消息。
- Agent 文本支持 Markdown，包括标题、列表、代码块和表格。
- 流式内容到达时持续追加，并显示生成中的状态。
- 回答完成后提供复制、重新生成和继续追问操作。
- 较长回答支持内容分段，避免所有阶段消息堆成大量聊天气泡。
- 中间过程与最终答案在视觉上明确区分，最终结论应最突出。

### 4.4 执行过程

根据后端当前阶段显示 Agent 的工作进度：

| 后端阶段 | 前端用户文案 | 建议展示内容 |
| --- | --- | --- |
| `INTENT` | 理解问题 | 识别出的分析意图 |
| `EVIDENCE` / `SCHEMA_RECALL` / `SCHEMA` | 查找相关数据 | 命中的表和字段摘要 |
| `ENHANCE` | 补全分析条件 | 增强后的问题 |
| `FEASIBILITY` | 检查可执行性 | 是否具备分析条件 |
| `PLANNER` | 制定分析计划 | 计划步骤 |
| `PLAN_EXECUTOR` | 执行分析计划 | 当前步骤及完成情况 |
| `SQL_GENERATE` | 生成查询 | SQL 摘要，可展开查看原文 |
| `SQL_CONSISTENCY` | 检查查询 | 校验状态和问题提示 |
| `SQL_EXECUTE` | 查询数据 | 执行状态、耗时和结果行数 |
| `SQL_REPAIR` | 修复查询 | 修复原因和重试次数 |
| `RESULT` | 整理结果 | 最终结论、表格和图表 |
| `HUMAN_FEEDBACK` | 等待确认 | 人工审核操作 |

交互要求：

- 默认只展示“正在做什么”和步骤是否完成，不直接滚动输出所有原始事件。
- 当前步骤有明确的运行状态；已完成、失败和等待确认使用不同视觉状态。
- 用户可以展开某一步查看 SQL、JSON payload、耗时和错误详情。
- 执行完成后保留过程记录，方便复盘。

### 4.5 数据结果

后端返回 `RESULT_SET` 或结果 payload 时，前端应根据数据类型选择合适的展示方式：

- **摘要**：展示 Agent 对结果的自然语言解释和关键结论。
- **数据表格**：支持横向滚动、列宽调整、排序和空值显示。
- **图表**：优先支持柱状图、折线图和饼图，并允许切换回表格。
- **SQL**：使用代码高亮展示，支持复制。
- **指标卡**：对单个核心数值展示数值、单位和必要的变化说明。
- **导出**：后续支持将表格导出为 CSV，将分析结果导出为 Markdown 或图片。

第一版应先保证摘要、SQL 和表格稳定展示，图表与导出可以放在第二阶段。

### 4.6 人工审核

当流程进入 `HUMAN_FEEDBACK` 时：

- 明确提示流程已暂停，而不是显示为连接中断。
- 展示待审核的分析计划、SQL 或其他上下文。
- 提供“批准继续”和“退回修改”操作。
- 退回时允许填写修改意见。
- 提交审核结果后继续使用同一个 `threadId` 执行。

### 4.7 连接与错误处理

- 显示后端连接状态，但不让连接信息占据主要界面。
- 区分业务错误、网络错误、用户主动停止和后端正常结束。
- 流式请求意外中断时保留已收到的内容，并提供重试入口。
- 重试时避免重复插入已经收到的事件。
- 请求超时、无数据、SQL 执行失败等场景使用易懂的说明，并允许展开技术详情。
- Ping 仅作为设置页或开发者工具中的诊断能力，不放在主要对话界面。

### 4.8 设置与开发者工具

普通设置包括：

- 后端服务地址。
- 默认 Agent。
- 主题和界面缩放。
- 是否启用人工审核。

开发者模式包括：

- 当前 `threadId`、事件序号和时间戳。
- 原始 SSE 事件列表。
- JSON payload 查看器。
- 请求地址、连接状态和错误栈。
- Ping 流测试。

技术配置不应长期占用聊天主界面，应集中放在设置或可展开的调试面板中。

## 5. 关键页面

### 5.1 首次进入 / 空状态

- 简短说明 DataAgent 能做什么。
- 显示 3 至 4 个真实的分析示例。
- 输入框位于页面视觉中心，鼓励用户直接提问。
- 后端未连接时给出设置入口。

### 5.2 会话工作区

- 左侧显示历史会话。
- 中间显示连续的用户问题和 Agent 回答。
- 右侧显示当前执行计划及详情。
- 输入区固定在底部，但不遮挡消息内容。

### 5.3 设置页

- 服务连接配置。
- Agent 与审核设置。
- 外观和客户端行为设置。
- 连接诊断与版本信息。

## 6. 页面状态

界面实现时至少覆盖以下状态，避免只设计“正常完成”的理想路径：

| 状态 | 用户可见反馈 |
| --- | --- |
| 空闲 | 可输入问题或选择示例 |
| 正在连接 | 显示短暂连接状态，可停止 |
| 正在执行 | 显示当前阶段、流式内容和停止按钮 |
| 等待人工审核 | 显示审核卡片与批准/退回操作 |
| 已完成 | 展示最终结论及结果操作 |
| 用户停止 | 保留已有内容并标记已停止 |
| 网络中断 | 保留已有内容，显示重试按钮 |
| 业务失败 | 显示可理解的错误原因和技术详情入口 |
| 无结果 | 说明未查到数据，并建议调整问题 |

## 7. 前后端数据约定

当前核心接口：

```text
GET /api/stream/search-lite
Content-Type: text/event-stream
```

请求参数：

| 参数 | 说明 |
| --- | --- |
| `agentId` | 当前 Agent 标识 |
| `threadId` | 会话线程标识，首次请求可不传 |
| `query` | 用户问题 |
| `humanReview` | 是否启用人工审核 |
| `humanFeedbackApproved` | 人工审核结果 |
| `humanFeedbackComment` | 人工审核意见 |

流消息结构：

```ts
type SearchLiteMessage = {
  threadId: string
  stage: SearchLiteStage
  type: 'TEXT' | 'JSON' | 'SQL' | 'RESULT_SET'
  chunk?: string
  payload?: unknown
  done: boolean
  error?: string
  seq: number
  timestamp: string
}
```

前端处理原则：

- `message` 事件用于更新文本、阶段进度或结构化结果。
- `complete` 事件代表本次流程到达 `RESULT` 或 `HUMAN_FEEDBACK` 终态。
- `error` 事件代表后端业务错误；网络断开应由客户端单独判断。
- 使用 `seq` 排序和去重，不能把每次网络分块当成一条独立聊天消息。
- 同一阶段的连续文本 `chunk` 应合并展示，结构化 payload 应交给对应结果组件。

## 8. 非功能要求

- **桌面体验**：窗口可自由缩放，最小尺寸下仍能完成提问和查看结果。
- **性能**：高频流消息需要批量更新，避免每个 token 都触发完整页面重绘。
- **可靠性**：切换会话或关闭窗口时主动取消正在进行的请求。
- **可访问性**：核心操作支持键盘完成，文本和状态不能只依赖颜色区分。
- **可维护性**：会话、消息、执行过程、结果渲染和连接层拆分为独立模块。
- **安全性**：前端不保存数据库密码或模型密钥；SQL 默认只展示和复制，不在客户端直接执行。

## 9. 实施优先级

### P0：本轮界面重构必须完成

- 三栏桌面工作区及响应式折叠。
- 新建会话与本地历史会话。
- 聊天消息与固定底部输入区。
- Agent 执行阶段展示。
- 流式文本合并与最终答案展示。
- SQL、JSON 和表格的基础结果组件。
- 停止请求、断线提示和重试。
- 后端地址等技术配置迁移到设置区域。

### P1：核心体验完善

- 多轮会话持久化。
- 人工审核完整交互。
- 会话搜索、重命名和删除。
- 图表展示和结果导出。
- Markdown 渲染、代码高亮和复制操作。

### P2：产品化能力

- 多 Agent 切换与 Agent 配置。
- 数据源管理与权限展示。
- 文件上传和分析模板。
- 会话云端同步。
- 快捷键体系、自动更新和完整客户端设置。

## 10. P0 验收标准

1. 用户首次打开客户端时，能够在不理解 `agentId`、`threadId` 或 SSE 的情况下直接发起一次分析。
2. 请求执行期间能够看到当前阶段，窗口缩放不会导致输入区或结果区不可用。
3. Agent 的连续输出显示为一条逐步更新的回答，而不是大量零散消息。
4. 最终结果能够按文本、SQL、JSON 或表格正确展示。
5. 用户可以停止请求；流异常中断时已返回内容不会丢失，并且能够重试。
6. 同一会话可以继续追问，切换到其他会话后能够恢复已有内容。
7. 调试信息默认不干扰普通使用，但开发者可以从详情面板中完整查看。

## 11. 本轮暂不处理

- 用户注册、登录与团队权限体系。
- 生产级数据源管理。
- 在线支付或用量计费。
- 移动端适配。
- 插件市场和复杂 Agent 编排界面。

这些能力需要后端接口和产品范围进一步明确，不应阻塞当前桌面客户端的核心体验重构。
