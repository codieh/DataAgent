# DataAgent 前端参考图素材拆解建议

## 结论

这组参考图属于以排版、分栏、数据可视化和状态反馈为核心的桌面产品界面，约 **95% 可以直接用前端代码实现**。它没有依赖摄影、3D 渲染、复杂插画或不可重复的背景图，因此不建议把界面区块切成图片使用。

真正值得单独准备的视觉素材很少：品牌 Logo、应用图标、可选的纸张噪点纹理，以及统一的图标资源。折线图、时间线、SQL 高亮、状态波纹、表格、按钮和窗口分栏都应该由代码生成，才能适配真实数据、窗口缩放、交互状态和主题变化。

## 统一界面骨架

五张图共用同一套客户端结构：

```text
App Window
├── Native Title Bar / Drag Region
├── Sidebar 或 Settings Navigation
├── Main Workspace
├── Inspector / Action Panel / Stream Monitor
└── Composer 或 Bottom Status Area
```

### 应由代码实现

- Electron 无边框窗口、拖拽区域、窗口控制按钮和标题栏。
- 可收起、可调整宽度的左右分栏。
- 页面切换、会话选中状态、悬停状态和键盘焦点。
- 全部文字、按钮、输入框、下拉框、开关、标签页和提示信息。
- 暖白背景、深绿色面板、细分隔线、圆角、阴影和网格。
- 响应式布局：宽窗口三栏，中等窗口收起右栏，窄窗口将左栏变成抽屉。
- 主题变量、字体层级、间距、边框、状态色和动画。

### 建议单独准备

| 素材 | 必要性 | 建议格式 | 说明 |
| --- | --- | --- | --- |
| DataAgent 品牌标志 | 必需 | SVG | 需要横版 Logo 和仅图形 Mark 两个版本 |
| Electron 应用图标 | 必需 | SVG 源文件，并导出 ICNS/ICO/PNG | 用于 Dock、安装包、窗口和关于页 |
| 功能图标集 | 必需但不需生成图片 | SVG 图标库 | 建议选一套统一线性图标，不要使用 PNG |
| 纸张微噪点 | 可选 | 256×256 PNG/WebP，可平铺 | 透明度应极低，也可以纯 CSS 生成 |
| 字体文件 | 视授权情况 | WOFF2 | 中文正文与拉丁/数字需要明确字体回退方案 |

## 页面 1：新会话首页

参考图：[01-new-session.png](./01-new-session.png)

### 页面结构

1. 顶部标题栏：Logo、前进后退、服务状态和窗口操作。
2. 左侧会话栏：新建分析、搜索、分组历史会话、数据源与设置。
3. 中央欢迎区：产品标签、主标题、说明和三个示例问题。
4. 右侧留白区：浅色技术网格与竖排概念文案。
5. 底部输入器：问题输入、附件、数据源选择和发送按钮。

### 可以用代码实现

- 会话分组、选中行、时间文字和搜索框。
- 主标题和示例问题的编辑式排版。
- 背景点阵/网格：使用多个 `linear-gradient` 或伪元素绘制。
- 右侧竖排文字：使用 `writing-mode: vertical-rl`。
- 输入器、附件按钮、下拉菜单和圆形发送按钮。
- 示例问题悬停时的箭头移动和分隔线动画。
- 服务状态点及其连接状态变化。

### 需要单独准备的素材

- 品牌横版 Logo 和图形 Mark。
- 可选纸张噪点纹理。

除此之外无需生成背景图。网格和装饰短线由 CSS 绘制会更清晰，也能随窗口尺寸变化。

## 页面 2：分析工作区

参考图：[02-analysis-workspace.png](./02-analysis-workspace.png)

### 页面结构

1. 左侧会话栏：历史会话与当前会话。
2. 中央对话区：用户问题、Agent 连续回复、相关数据表和 SQL 折叠区。
3. 底部输入器：分析模式、数据源、停止生成。
4. 右侧执行面板：过程/详情标签、阶段时间线和当前节点详情。
5. 两条可拖拽分栏线。

### 可以用代码实现

- 三栏 Grid/Flex 布局及拖拽调整宽度。
- 流式文字合并、打字光标和生成状态。
- Agent 阶段时间线，包括完成、执行中、待执行和错误状态。
- 当前节点的铜色同心脉冲：CSS keyframes 即可。
- 阶段展开/收起、步骤耗时和事件回执。
- 数据表标签、关系图入口和 SQL 折叠面板。
- 停止按钮、快捷键提示和滚动位置管理。
- 详情面板中的 JSON、Payload 和原始 SSE 事件。

### 需要单独准备的素材

本页没有必须生成的位图素材。时间线节点、数据库图标、关系图图标和停止图标都应使用 SVG/CSS。

如果后续要展示真实“表关系图”，应使用可交互图组件绘制节点和连线，而不是生成静态关系图图片。

## 页面 3：结果探索页

参考图：[03-result-exploration.png](./03-result-exploration.png)

### 页面结构

1. 左侧会话栏。
2. 结果标题区：完成状态、结论标题、解释和导出操作。
3. 主图表区：30 天销量折线图、异常时间区间和注释。
4. 关键发现区：编号洞察和核心变化指标。
5. 数据区：数据表、SQL、分析依据标签页。
6. 右侧收起状态栏与底部追问输入器。

### 可以用代码实现

- 折线图、坐标轴、网格线、Tooltip、异常区间和图表注释。
- 建议使用 ECharts；如果追求更精细的定制，可使用 SVG/D3。
- 巨大的半透明“30”作为排版装饰，由文字和 CSS 实现。
- 关键发现编号、指标数字和上下文说明。
- 表格排序、分页、异常标记、横向滚动和列宽调整。
- SQL 抽屉、语法高亮、复制和展开操作。
- CSV/Markdown 导出与结果复制。
- 右侧工具轨道的收起/展开状态。

### 需要单独准备的素材

本页不需要静态图表素材。图表必须根据后端结果动态生成，否则无法适配真实数据、Tooltip、筛选和导出。

只有在实现“将结果导出为图片”时，才需要在运行时将图表和结论画布导出为 PNG，这属于程序输出，不是预制素材。

## 页面 4：人工审核页

参考图：[04-human-review.png](./04-human-review.png)

### 页面结构

1. 极窄深色会话栏。
2. 左侧审核文档：暂停状态、执行计划、SQL、查询范围和安全提示。
3. 右侧深绿操作区：步骤编号、审核问题、批准、退回和修改意见。
4. 底部元信息：线程 ID、暂停时间和连接状态。

### 可以用代码实现

- 双色分屏和动态宽度布局。
- 执行计划时间线、暂停状态和查询范围摘要。
- SQL 编辑器的只读模式、行号、语法高亮和复制。
- “批准并继续”和“退回修改”的按钮状态及快捷键。
- 退回意见字数统计、必填校验和提交反馈。
- 深绿面板的微弱材质感、超大步骤数字和元信息分隔。
- 审核后恢复同一个线程的执行状态。

### 需要单独准备的素材

- 可复用品牌 Mark。
- 可选的深色细噪点纹理，与浅色背景纹理可以来自同一张透明噪点图。

盾牌、暂停、时钟和连接图标应来自 SVG 图标集。SQL 代码不应做成图片。

## 页面 5：设置与连接诊断

参考图：[05-settings-diagnostics.png](./05-settings-diagnostics.png)

### 页面结构

1. 顶部客户端标题栏。
2. 左侧设置导航。
3. 中央配置表单与 Ping 诊断结果。
4. 右侧 Stream Monitor：连接信息、心跳图和事件日志。

### 可以用代码实现

- 设置导航、输入框、下拉框、开关和缩放选择。
- 后端地址校验、连接状态和 Ping 测试按钮。
- DNS、TCP、HTTP、SSE 四阶段诊断时间线。
- 网络警告、成功状态和错误详情。
- Stream Monitor 的属性列表和事件日志表格。
- 心跳折线图：Canvas 或 SVG 实时绘制。
- 右侧监控面板收起、事件/Payload 标签切换。
- 日志虚拟滚动、自动跟随和暂停查看。

### 需要单独准备的素材

本页不需要额外位图。心跳图和事件数据都必须实时绘制。开发者工具图标建议使用同一套 SVG 图标。

## 不建议生成图片的元素

以下元素虽然视觉上比较突出，但全部应使用代码实现：

- 折线图、心跳波形、异常区间和所有数据图形。
- 执行阶段时间线和进度节点。
- SQL 代码、行号和语法高亮。
- 表格、分页、排序和异常标签。
- 背景网格、横线、竖线、状态点和脉冲圆环。
- 超大数字“30”“05”和竖排文字。
- 窗口按钮、数据库、复制、导出、设置等功能图标。
- 所有按钮、输入框、面板、阴影和边框。

把这些内容做成图片会造成文字模糊、缩放失真、暗色模式困难、状态无法变化以及无障碍支持缺失。

## 建议建立的素材目录

```text
src/assets/
├── brand/
│   ├── logo-horizontal.svg
│   ├── mark.svg
│   └── app-icon.svg
├── textures/
│   └── paper-noise.webp
└── fonts/
    ├── ui-sans.woff2
    └── ui-mono.woff2
```

图标不建议逐个复制到素材目录。更适合统一使用一套 React SVG 图标库，并封装尺寸、线宽和颜色规则。

## 素材制作优先级

### P0：开始写界面前确定

1. DataAgent 横版 Logo、方形 Mark 和应用图标。
2. 字体方案及商用授权；优先确认中文字体在 macOS、Windows 上的表现。
3. 图标体系：统一为 1.5px 或 1.75px 线宽，避免混用多套风格。
4. 颜色、边框、圆角、阴影、间距和字号设计变量。

### P1：视觉精修阶段补充

1. 极轻的透明纸张噪点纹理。
2. 应用安装包所需的 ICNS、ICO 和不同尺寸 PNG。
3. 空状态或错误状态插图；只有确实需要情绪化表达时再单独设计，不应为了填空强行加入。

## 最终建议

本项目不需要先生成一批复杂视觉素材再开发。最合理的路线是：先确认品牌标志、字体和图标体系，然后用代码还原所有界面结构和数据视觉，最后只用一张极轻噪点纹理做材质精修。

当前唯一值得单独设计而不是直接编码的核心资产，是 **DataAgent 品牌系统与应用图标**。其余关键视觉价值来自排版比例、分栏行为、真实数据、状态动画和细节一致性，而不是图片素材。
